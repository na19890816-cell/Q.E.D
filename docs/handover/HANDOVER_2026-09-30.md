### Phase 3 — G3 実装: CUSUM + AlphaLifecycleEngine

#### frost_cusum.py

**CUSUM 数理仕様 (Page 1954)**:

```
下方 CUSUM: S_neg[t] = max(0, S_neg[t-1] - (v[t] - mu0 + k))
上方 CUSUM: S_pos[t] = max(0, S_pos[t-1] + (v[t] - mu0) - k)

中立点 = mu0 - k  (デフォルト: 0.0 - 0.5 = -0.5)
v > 中立点 → S_neg は増加しない（正常範囲として無視）
v < 中立点 → 差分が S_neg に蓄積される
```

**重要な数値根拠** (デフォルト k=0.5, h=5.0, mu0=0.0):

| IC 値 | 増分/step | h=5.0 到達ステップ数 |
|-------|----------|-------------------|
| -0.8 | 0.3 | 17 (first_idx=16) |
| -1.0 | 0.5 | 10 (first_idx=9) |
| 0.0 | 0 | 到達しない（正常） |
| 0.1 | 0 | 到達しない（正常） |

```python
@dataclass(frozen=True)
class CusumParams:
    k: float = 0.5; h: float = 5.0; mu0: float = 0.0

@dataclass
class CusumDetector:
    params: CusumParams
    def step(self, value: float) -> CusumStepResult: ...
    def run(self, values: List[float]) -> CusumRunResult: ...
    def reset(self) -> None: ...
    @classmethod
    def from_config(cls, config) -> "CusumDetector": ...

def detect_degradation_cusum(rolling_ic, k=0.5, h=5.0, mu0=0.0) -> bool: ...
```

#### frost_lifecycle.py

```python
class LifecycleStatus:
    ACTIVE = "active"; DEGRADED = "degraded"; UNDER_REVIEW = "under_review"
    REVOKED = "revoked"; SUSPENDED = "suspended"
    ALL: tuple  # 5 要素

@dataclass
class LifecycleRecord:
    artifact_id: str
    current_status: str = LifecycleStatus.ACTIVE
    rolling_ic: List[float]   # 昇格後の rolling IC 時系列（古い順）
    metadata: Dict[str, Any]

@dataclass
class LifecycleCheckResult:
    artifact_id: str; current_status: str; new_status: str
    degradation_detected: bool; cusum_result: Optional[CusumRunResult]
    rolling_ic_len: int; review_required: bool; reason: str
    status_changed: bool  # property
    def to_dict(self) -> Dict[str, Any]: ...

@dataclass
class KillQueue:
    pending_reviews: List[LifecycleCheckResult]
    count: int         # property
    artifact_ids: List[str]  # property
    def to_dict(self) -> Dict[str, Any]: ...

@dataclass
class AlphaLifecycleEngine:
    params: CusumParams = CusumParams()
    min_ic_len: int = 10
    def check(self, record: LifecycleRecord) -> LifecycleCheckResult: ...
    def check_batch(self, records) -> List[LifecycleCheckResult]: ...
    def build_kill_queue(self, records) -> KillQueue: ...
    @classmethod
    def from_config(cls, config) -> "AlphaLifecycleEngine": ...

def check_alpha_degradation(artifact_id, rolling_ic, params=None, min_ic_len=10) -> LifecycleCheckResult: ...
```

**ステータス遷移ルール**:
- `REVOKED` / `UNDER_REVIEW` → **再検査スキップ**（review_required=False を返す）
- `rolling_ic < min_ic_len` → **CUSUM スキップ**（current_status 維持）
- `DEGRADED` 状態でも次回 CUSUM 未検知なら `ACTIVE` に**自動復帰**
- `SUSPENDED` → CUSUM 検査**対象**（REVOKED/UNDER_REVIEW と異なる）

**半自動 Kill 方針**: 即時自動 Kill は実装しない。CUSUM Detect → KillQueue 追加 → 人間承認 → REVOKED の3段階。

## 5. 未着手項目（次セッションへの引き継ぎ）

### 最優先: NOTE-001 (G1) — Deflated Sharpe Ratio (DSR)

**ファイル**: `docs/notes/NOTE-001-deflated-sharpe-ratio.md`  
**ステータス**: Note登録済み・**未実装**  
**優先度**: **最優先**（憲法ギャップ中で最も重要）

**概要**:  
DSR (Deflated Sharpe Ratio) は、多重仮説検定の文脈で「試行回数 N を考慮した上で本当に有意な SR か」を検証する指標。  
単純な SR では多数の戦略を試した場合の過学習を見抜けないため、憲法が義務付けている。

**前提条件（実装前に必要）**:

1. **試行回数 N の集計基盤**: どのアルファが何回試行されたかのカウントが必要
   - ADR-002（系譜ログ）との依存関係あり
   - `knowledge_artifacts` テーブルに `trial_count` または `lineage_id` が必要

2. **ADR-002 系譜ログ設計**: 同じシグナルの派生関係を追跡するログ設計
   - **DSR 実装の直接的ブロッカー**

**実装候補場所** (`frost_cusum.py` と同様の新規ファイル):
```
analytics/python/frost/frost_dsr.py   — DSR 計算ロジック
analytics/python/frost/gate_dsr.py    — DSR ゲート（gate_engine.py への統合候補）
```

**数式** (Bailey & López de Prado 2014):
```
DSR = SR * sqrt((T - 1) / T) * (1 - γ*SR + SR²/2 * (1 - γ + γ²)) ** (-1/2)
  ここで: T = 観測数, γ = 歪度, SR = 標本シャープレシオ
  SRₒ (ベンチマーク SR) は試行回数 N から導出
```

**注意**: ADR-002 系譜ログが整備されていない場合、N を固定値（例: `N=1`）で仮実装する選択肢もある。  
その場合は DSR ≈ SR（退化版）になるが、インターフェースを先に確立できる。
